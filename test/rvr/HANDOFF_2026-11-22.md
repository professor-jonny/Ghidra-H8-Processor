## Addendum (2026-11-22, later session): limp table, lambda flag, MUT profile

### 11dc9 "Limp Mode Fueling Table"
- Same table as the VR4/Evo "Limp Mode Fueling Table (MAF Fault)". Path: F2D0 -> F2D4 pulse base, used when F25A bit0 or F25A&3 is set (fuel_pw_and_airvol_compute, 0x2a460).
- F20E writers traced; none involve a MAF fault, so the limp use is unproven on the RVR. The XML name comment says so.
- 10814 (0x0048) added as "LimpHome Scaling"; 11ebe added as Accel Enrichment TPS Delta Multiplier (reader not traced).
- Wastegate duty / boost load tables 12a9a/12aae/12ac2/12ad6 renamed by F0F8 bit5 variant.

### Lambda flag chain
- F1FE bit3 is set by lambda_enable_flag_update (0x21942) when EF96 == 0 or config byte 0x10201 is 6/7/8. RVR has 0x10201 = 0.
- F20E bit1 mirrors F1FE bit3. EF96 reloads to 12 when F20E & 0x11 and counts down on the F208 bit0 tick (base tick period unknown).

### EvoScan logs (test/rvr/ecu logs, 3 files)
- Pulse width follows AirFlow/RPM (0.82-0.93 correlation), which points to the normal airflow path. Closed-loop rows cover a narrow range, so this is not conclusive.
- Definitive test: log RequestID 0x1E (F20F) and 0x71 (F1FF) through cold start, idle and light cruise.

### MUT table and logging profile
- adc_sensor_convert_single bound is the word at ROM 0x3282, so IDs above 0x95 are real entries. IDs 0xC0+ are 16-bit reads handled by the SCI1 actuator dispatcher.
- Dead cells F0BB/F0BA: 0x96-0x99, 0xA1-0xA3, 0xB4-0xBF, 0xE1-0xFF.
