- **Why experiment 2 (item 0, 2026-11-04) concluded "stackshift is not the lever": its attribution is confounded.** The drift accumulates down the function: every earlier call raises the SP for all later calls, so a store at a call reflects the SUM of the earlier callees' drift, not its own callee's group. `zero_ram_range` alone leaves +2 for every later call even when the later callees have stackshift 0. In the example function all callees were stackshift 4 anyway. So "do not change stackshift further" is NOT supported; treat that conclusion as withdrawn until the cumulative test below is done.

**Where things stand (verified)**
- **Call-graph mode** added to `H8PreservedRegsAnalyzer` (option "Call-graph mode (also preserve R1/R2 in functions that never write them)", off by default; the analyzer itself is still disabled by default). Per function it takes the R1/R2 bits written by the function's own p-code (any overlapping register write), adds the writes of every callee and tail-jump target (whole-program least fixpoint, so recursion is handled), and removes the registers the function saves and restores. A function left with no writes to R1/R2 gets the matching `_pR1/_pR2/_pR1R2` clone. Anything unresolved counts as writing both: register-indirect calls (`pjsr @R0`), computed jumps without targets, calls or jumps to an address that is not a function entry, functions with no instructions.
